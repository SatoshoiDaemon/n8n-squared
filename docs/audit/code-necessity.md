# Necessidade de código e decisões

## Escala de decisão

| Classificação | Uso nesta auditoria |
|---|---|
| MANTER | Dá suporte direto a workflow, segurança, persistência, extensibilidade ou operação. |
| SIMPLIFICAR | Faz falta, mas o caminho padrão pode ser menor ou configurado com limites claros. |
| CONSOLIDAR | A mesma função tem entradas, módulos ou cópias de configuração redundantes. |
| SUBSTITUIR | A capacidade é útil, mas a implementação adequada ao Squared ainda não existe ou o fornecedor atual não serve. |
| REMOVER | Não entrega valor ao produto ou é um caminho de execução sem uso no perfil Square. |
| INVESTIGAR | Evidências não permitem decidir com segurança; usar somente quando a inspeção abaixo não resolve a dúvida. |

As recomendações distinguem a fonte do repositório, o fechamento instalado e os módulos realmente inicializados. Remover um pacote do ZIP pode reduzir bytes e instalação sem mudar RSS; retirar um módulo carregado pode alterar memória, mas a diferença ainda precisa ser medida.

## Remoções concretas propostas

1. Retirar por completo o trial/upgrade modal, pesquisa NPS e pesquisa de perfil, incluindo o disparo associado ao salvamento do workflow, stores, rotas/API exclusivas, eventos, traduções e tracking.
2. Retirar PostHog/RudderStack e experimentos de marketing; antes, trocar usos de feature flags que controlam funcionalidade útil por configuração local explícita.
3. Retirar engine-v2 da distribuição inicial: eliminar a dependência runtime, módulo, comando e banco de data plane separado se a decisão de produto continuar sendo uma aplicação única.
4. Reduzir a lista de nodes e provedores entregues por padrão. Essa mudança precisa produzir um mapa de compatibilidade de workflows próprios do Squared, sem preservar nodes só por causa do upstream.
5. Excluir o driver SQLite do ZIP se o artefato passar a exigir PostgreSQL externo. Manter a configuração de SQLite no ambiente local somente se continuar útil aos testes.

## Limite das estimativas de código

As quantidades de linhas são aproximações da árvore TypeScript/JavaScript indicada, incluindo testes quando mencionados. Elas medem superfície de código candidata, não código morto, tempo de remoção nem redução de memória. Dependências indiretas e referências fora dessas árvores precisam ser reavaliadas ao executar cada remoção.
